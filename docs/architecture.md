# Архитектура и декомпозиция

**Контекст:** внешняя обработка 1С, управляемая форма. Не требуется менять общую конфигурацию у клиентов с разными базами.

1. Пользователь выбирает файл асинхронно; файл поступает в серверный контекст через временное хранилище.
2. Сервер проверяет входные данные и считывает DBF. Порядок и типы колонок выходного файла сохраняются при формировании ответа на основе исходного файла.
3. Поиск ЛС отделён от сопоставления категорий услуг: номер договора может отличаться в двух источниках.
4. Поиск по адресу не должен молча разрешать неоднозначность. Для строки без квартиры совпадение с конкретной квартирой не допускается.
5. Таблица соответствий услуг хранит ручные решения отдельно от автоматических правил; «Не выгружать» — редактируемая категория.
6. Финансовые показатели получают за явно заданный расчётный период; после изменения назначения услуги суммы нужно пересчитать.
7. Пользователь проверяет число загруженных/обработанных строк и отмеченные не найденные ЛС перед выгрузкой.

## Важные ограничения

- Демонстрация на Python показывает только чистую бизнес-логику поиска. Она **не** реализует DBF/XBase, 1С-клиент и SQL-запросы регистров.
- Не утверждается совместимость с web-клиентом без отдельной проверки в целевом окружении.
- Не публикуются имена внутренних объектов, ссылки и текст производственного модуля.
