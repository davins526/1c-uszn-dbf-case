# Как этот подход раскладывается на 1С (концептуальная схема)

Это **авторское описание архитектуры**, а не экспорт исходного рабочего модуля и не компилируемый BSL-проект. Здесь нет закрытых запросов или имён объектов конкретной конфигурации.

| Этап | Контекст 1С | Ответственность |
|---|---|---|
| Выбор DBF | клиент, управляемая форма | асинхронный выбор и передача файла во временное хранилище |
| Чтение файла | сервер | проверка двоичных данных, XBase, временный каталог, освобождение ресурсов |
| Поиск ЛС | сервер | кандидаты по улице/дому/корпусу/квартире, отказ от неоднозначного совпадения |
| Сопоставление услуг | сервер + данные формы | автопредложение + приоритет выбранной пользователем категории |
| Получение начислений | сервер | выборка по заданному периоду, заполнение только разрешённых полей |
| Сохранение O-файла | сервер + клиент | сохранение структуры исходного DBF, выдача результата пользователю |

## Почему демонстрационный модуль на Python?

Чтобы открытый код можно было запустить без корпоративной базы, лицензированной 1С-конфигурации и чувствительных данных. Для исходной внешней обработки требуются реальная конфигурация, объектная модель и разрешение правообладателя. Демонстрация `demo/matching.py` изолирует только переносимые правила и покрывает их тестами.
